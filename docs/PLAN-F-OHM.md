2026-08-07 설계. 목표: 시나리오 프리셋의 국경을 "현대 행정구역을 시대 소유주에

## 확인된 사실 (2026-08-07 프로브)

- 벡터 타일: `https://vtiles.openhistoricalmap.org/maps/ohm/{z}/{x}/{y}.pbf`
  (앱이 이미 스트리밍하는 그 서버 — z2 타일 2.8MB, 브라우저 fetch 성공).
- `land_ohm_lines` 레이어: 경계 **선** 26,642개(z2 한 장 기준), 속성
  `admin_level`, `start_date`/`end_date` + 수치형 `start_decdate`/`end_decdate`,
  `maritime`, `disputed`, `disputed_by`.
- `land_ohm_centroids` 레이어: 정치체 라벨 중심점 — `name`, `admin_level`,
  날짜쌍, `area_km2`. 폴리곤 소속 판정의 열쇠.
- 날짜 필터는 스타일이 아니라 **속성**에 있다: 앱의 maplibre-gl-dates가
  하는 일을 추출기는 속성 비교(`start_decdate <= D < end_decdate`)로 한다.

## 산출물 형식 (기존 기계와 접합)

기존 파이프라인을 그대로 탄다:

1. `scripts/extract-regions.mjs` — regions.pmtiles → `regions-seed.geojson`
   (타일 조각 스티칭 + polygon-clipping 유니온). **이 패턴의 자매 스크립트**로
   `scripts/ohm/extract-era-borders.mjs`를 만든다: 입력이 로컬 pmtiles가 아니라
   OHM 타일/오버패스이고, 날짜 D가 매개변수인 점만 다르다.
2. `scripts/presets/build-preset.mjs` + `*.spec.mjs` — 스펙이 소유권을 배정해
   시나리오 폴더를 생성. 시대 지오메트리는 시나리오 자산
   (`regions.geojson` — JSON_URLS.regionsGeojson가 이미 읽는 그 파일)으로
   들어간다.

## 추출 경로 두 가지

- **경로 1 — 타일 폴리곤화 (검증됨, 거칢)**: z2–4에서 `land_ohm_lines`를
  날짜 D로 필터 → admin_level ≤ 2 선들을 노딩·폴리곤화(turf/polygonize) →
  면(face)마다 같은 날짜의 `land_ohm_centroids` 포함 판정으로 정치체 배정.
  장점: 서버 한 곳, 전 지구 한 번에. 단점: 선→면 조립의 위상 잡음,
  타일 경계 스티칭(기존 round5 유니온 기법 재사용).
- **경로 2 — 오버패스 관계 조립 (정밀)**: OHM 오버패스에서
  `relation[type=boundary][admin_level=2]` + ISO 날짜 문자열 비교
  (`t["start_date"] <= "1939-09-01"` — ISO는 사전순=시간순)로 시대 관계를
  받아 멤버 웨이로 링을 조립. 장점: 정치체별 정확한 멀티폴리곤.
  단점: 요청 수·속도 제한, 조립 코드.

권장: **경로 1로 전 지구 골격 → 경로 2로 주요 분쟁 경계만 정밀 교체**.
검수는 Omniatlas/GeaCron 화면과 눈 대조(링크만 기록).

## 단계

- F-1: `scripts/ohm/extract-era-borders.mjs` 골격 — 날짜 D, bbox, zoom을 받아
  필터된 경계선+중심점 GeoJSON 덤프 (조립 전 원자재 검사용).
- F-2: 폴리곤화 + 정치체 배정 + 스티칭 → `era-borders-<date>.geojson`.
- F-3: 프리셋 접합 — 스펙에 `eraGeometry` 필드를 주면 build-preset가 시대
  면으로 프로빈스를 **재단**한다(교체가 아니라 클립: 프로빈스 층은 살린다).
  게임 쪽 코드 변경 없음. **완료 2026-08-09, 아래 실측 절 참조.**
- F-4: WWII++ 1939로 1차 실증 (동프로이센, 전간기 폴란드 동부 국경이
  현대 배정판과 눈에 띄게 다른 지점 — 검수 앵커). **1차 통과 —
  `docs/analysis/f3-graft-1939-central-europe.png`: 회랑·크레시·빈 중재선
  모두 눈으로 확인.**
- F-5 (선택): admin_level 4 시대 하위구역 → 지역 단위 플레이 정밀화.

플레이어가 로컬에서 첫 덤프를 떴고(선 1.4MB·중심점 47KB), Cowork가 원본을
받아 측정했다. F-2 설계를 바꾸는 사실들:

- 선 5,552개(정점 21,309) / 중심점 180개. 추출기 로직 재검증 불일치 0.
- 구조 건전: 섬 폐곡선 376, 삼합점(차수3) 125. 타일 이음매는 대부분 양쪽
  타일이 같은 반올림 점으로 끝나 자기결합(차수2) — 이음매 근처 외톨이는
  42개뿐(반올림 흔들림 ~21쌍). → F-2는 ε-스냅으로 봉합.
- **admin_level 1 = 제국 계층**(대영제국·프랑스 식민제국 등 중심점 6, 선
  1,220)이 국가(2) 경계 위에 좌표까지 겹쳐 감 — 차수4 노드 973개의 정체.
  → **면(face) 조립은 admin_level 2 선만 사용**, 1은 참조용으로만 보존.
- **z2 중심점은 타일러가 면적순으로 솎는다**: 폴란드·독일·일본 라벨이 없다
  (경계선 자체는 있음). area_km2는 해역·극지 클레임 포함(호주 1.22억km²) —
  라벨 순위용 수치일 뿐. → **중심점 수집은 z4+에서** (덤프가 작아 비용 무시).
- 진짜 끊김(이음매와 무관한 차수1) 519개 — z2 단순화로 짧은 웨이 탈락 +
  OHM 미완 구간(멕시코-미국 국경 표본 다수). → F-2: 선은 z3–4로 뜨고,
  스냅 후에도 못 닫힌 면은 중심점 0개/2개+ 면과 함께 **국가별 현대 배정
  (Tier A) 폴백 + 사유 로그** — 조용히 틀리지 않는다.
- 같은 영토의 중복 버전 실존(뉴펀들랜드: 자치령 1927→1949와 위원회정부
  1934→1949가 동시 유효 — OHM 데이터 결함). → **latest-start 우선 + 충돌
  로그** 규칙.
- 창 규칙 실증: 소련 1926→**1939-10-06**(폴란드 전역 종료일 판갈이)이 9/1에

  (1935→1945)·영제국(1939-04-06→1940-06-14)이 등장. 시대 슬라이스가 진짜다.
- 다음 검증 러닝(로컬, 타일 4장): `node scripts/ohm/extract-era-borders.mjs
  1939-09-01 --zoom 4 --bbox 10,45,35,60` — 폴란드·독일 중심점 등장 여부와
  동프로이센 선 디테일 확인 → F-2 줌 파라미터 확정.

### z4m 재검증 — maritime 가설 기각 기록 (2026-08-09, 사용자 PC 실측)

- **maritime는 아무것도 안 닫는다**: admin_2 차수-1 끊김이 maritime 제외
  226 → 포함 225, 0.06° 스냅 후 44 → 45 (±1). 해안을 따라가는 경계는
  평범한 admin_2 선이고(단치히만 현장 검증: 만 연안 전 구간 maritime 태그
  없음, 1920-01-10→1939-10-26 베르사유 판), maritime=yes는 먼바다 경계뿐
  — 오히려 제 끊김을 새로 들여온다. → **F-2는 F-1 기본값 그대로 maritime
  제외.**
- 단치히만 "미결"은 지표 오류였다(홀수 차수 지표에 정상 삼합점 혼입).
  실제로는 0.022° 갭 — 스냅 범위 안.
- **버퍼 오버슛 발견**: 끊김 일부가 정확히 타일 경계 + 1.40625°(타일폭/16,
  MVT 버퍼 256/4096)에 정렬 — x=23.90625 삼중 표본(보트니아만). 타일러가
  일부 지오메트리를 버퍼째 내보낸다. → F-2 디코드에 **타일 정확 경계 클립**
  단계 추가: 버퍼 중복 제거 + 이음매 결합 보장.
- **F-2 파이프라인 확정(수정판)**: ① admin_2, maritime 제외 → ② 타일 정확
  경계 클립 → ③ round5 병합 + 0.06° 스냅 → ④ 면 조립 → ⑤ 오버패스 이름
  배정 → ⑥ 현대 육지 마스크(regions-seed 유니온) 클립 — 바다 면 제거·해안
  정밀도·해안 누수 면 복원 겸용 → ⑦ 미배정/다중 배정 면은 국가별 현대
  배정(Tier A) 폴백 + 사유 로그. admin_1(제국 계층)은 조립 제외.

## 전세계 커버리지 실측과 출처 사다리 (2026-08-09, 플레이어 관측 + 실측)

플레이어가 OHM 사이트에서 아시아 부실을 관측 → 전 지구 재점검(1939 z2,
지역별 정점수/유효 정치체수). 결과, **1939 유효 폴리곤 지도는 사실상
식민제국 지도다**: 아프리카 51개(!), 중동 16, 동남아 15(말레이 보호령

있다. 반면 **유럽 대륙 주요국 전멸**(독일·프랑스·이탈리아 본토·스페인·
폴란드·베네룩스·덴마크·핀란드·발트 2/3·체코·헝가리·루마니아·유고·스위스

## 클로드 코드 리뷰 회신 (2026-08-09 — 로컬 세션, 열린 문제 6건 검토 의견)

검토 범위: assembleFaces.mjs 전문(노딩 루프 216-330, 스냅 344-420, 해안 융합
698-725), 브리핑의 재현 실측 기록. **구현은 전부 Cowork 레인** — 아래는 의견과
우선순위만.

1. **지중해 메가면** — 브리핑의 후보 접근(열린 사슬 끝 해안-해안 우선 용접)에
   동의하되, 용접 전에 계측을 넣을 것: 융합 후 열린 사슬 끝마다 최근접 해안
   끝점까지의 거리를 로그로 히스토그램화하면 갭의 스케일이 바로 보인다. 갭이
   2×SNAP_TOLERANCE(0.12°) 미만이면 **해안-해안 쌍에만 한정한 더 큰 관용치
   용접**이 안전하다(육지 국경은 건드리지 않으므로 스냅 연쇄 위험 없음). 리옹만
   왕복 흔적은 "양쪽이 같은 면인 비분리 해안"의 표준 서명이므로, 메가면의 면
   보행 엣지 시퀀스를 덤프해 육경→해안→육경 전환점을 찍는 국소 이분 탐색
   도구가 두 번째 결함부터의 비용을 크게 줄인다.
2. **독일 4-라벨 충돌면** — 갭 좌표 측정 후 표적 스냅 조정에 동의. 그 전까지의
   방어선으로 **다중 라벨 면은 최대 면적 라벨에 배정하고 경고를 찍는** 폴백을
   권장(침묵 병합 금지 원칙의 적용 — 지금은 한 면이 통째로 한 폴리티가 되는
   조용한 오답). 갭이 스냅 범위를 넘으면 OHM 업스트림 데이터 보고가 맞다.
3. **노딩 비수렴 ~6건/패스** — 코드에서 유력 원인을 확인: 교차점 게이트(t, u ∈
   (T_EPS, 1-T_EPS))는 **round5 이전의 t**로 판정하고, 분할점은 round5로 만든다
   (assembleFaces.mjs:300-303). 참 교차점이 내부에 있어도 반올림 좌표가 기존
   끝점 키와 일치하면 316행 필터가 분할을 버리고, 기하학적 교차는 남아 다음
   패스에 재검출된다 — 무한 재검출의 정확한 기전. 수리 제안: 반올림 좌표가
   끝점 키와 충돌하면 분할을 버리지 말고 **그 끝점을 상대 세그먼트에 투영해
   T-정션으로 분할**(addSplit(sj, u, 끝점 좌표))하면 한 패스에 해소된다.
   이 수리는 5번(성능)의 다패스 지배도 함께 줄인다.
4. **바티칸·모나코 z4 정책** — area_km2 임계 제외에 동의, 결정 권고: **임계
   25 km²**(모나코 2.0, 바티칸 0.44는 제외되고 리히텐슈타인 160은 살아남는
   측정 근거 있는 값). 제외된 정치체는 도려내지 않고 산출물에 메모 행으로
   남긴다(브리핑 제안 그대로).
5. **성능** — 3번 수리로 패스 수 자체가 줄어드는 것이 첫 수확. 그다음은 패스
   간 **더티 플래그**(직전 패스에서 분할이 닿지 않은 세그먼트 쌍은 재검사
   제외)와 그리드 셀 크기를 중앙값 세그먼트 길이의 ~2배로 맞추는 튜닝 순서.
   유럽 창 30초면 세계 런은 분 단위로 수렴 가능해 오프라인 파이프라인으로
   허용 범위.
6. **±180·내해** — 추출 단계에서 자오선 이음새를 용접하지 않는지(타일 경계가
   ±180과 겹치므로 스티칭이 경도 -179.99↔179.99를 이어붙이면 세계 런에서
   원통이 된다) 가드 확인이 선행. 내해는 "경계가 100% 해안이고 라벨 점이 없는
   면은 물로 남긴다"는 규칙이 있으면 카스피해가 자동 처리된다 — 규칙 존재
   확인, 없으면 추가 권고. 카스피해 창 런 1회로 검증 가능.

## 리뷰 이행 실측: 노딩 비수렴의 진짜 기전은 "계단" (2026-08-09 — Cowork)

회신 3번 이행 중 트레이스로 기전이 **한 단계 더 깊게** 확정됐다. 리포트에
`nodingPasses`(패스별 카운트)와 `--trace-noding`(3패스째부터 전 검출 기록,
상한 400 초과분 카운트)을 넣고 유럽 창을 다시 돌린 결과:

- 비수렴 잔량 전원이 **한 지점**이었다: 19.3782°E 42.063°N — 알바니아·
  몬테네그로 접경. 창 내 라벨 유실 1건(이탈리아령 알바니아)과 같은 자리.
- 기전은 "같은 교차 재검출"이 아니라 **계단 생성기**: 같은 국경의 두 사본이
  끝점이 round5 한 퀀텀(1e-5°) 차이로 나란히 수렴하는 팁에서, 정확 교차점이
  팁의 0.8~1.8퀀텀 앞에 놓인다. 반올림 분할점이 팁보다 한 퀀텀 아래 **새
  노드를 주조**하고 두 세그먼트를 거기 재정박 → 다음 패스에 같은 구성이 한
  칸 더 내려간 자리에서 재발. 매 패스 새 노드 하나씩 만들며 무한 하강.
  (회신이 짚은 316행 필터 폐기는 이 계단의 정확-일치 특수사례다 — 정확 키
  일치만 처리하는 수리로는 잔량 6건이 그대로였다. 실측으로 확인.)
- 수리(일반화된 T-정션): 정확 교차점이 어느 끝점의 **END_TOL=2e-5(2퀀텀)**
  안이면 그 끝점이 접점이다 — 상대 세그먼트만 그 끝점 좌표로 분할, 새 노드
  주조 금지. 근거: 계단 실측 0.8~1.8퀀텀 + round5 단독 변위 ≤0.71퀀텀.

## F-3 실측: 프리셋 접합 (2026-08-09 — Cowork, wwii-1939 실제 빌드)

**설계 결정 — 교체가 아니라 재단.** 초안 계획은 "regions.geojson을 시대판으로
교체"였지만 그대로 하면 프로빈스 층이 사라진다(나라 하나 = 지역 하나 → 정복할
땅이 없다). 실제 구현은 **시대 면으로 현대 프로빈스를 클립**한다. 엔진이 이미
가진 두 계약에 그대로 얹었다(Nations.jsx):

- 점 있는 GADM id + `edited: true` → 해당 id의 스톡 벡터 타일 채움을 끄고
  GeoJSON 지오메트리를 그린다("편집기가 모양을 고친 지역" 경로). 재단된
  프로빈스가 정확히 그것이다.
- 점 없는 id → 작가가 그린 지역, 항상 GeoJSON에서 그린다. 잘려나간 조각
  (`era_N`)이 여기로 간다.

id 정책: **가장 큰 조각이 원래 GADM id를 유지**한다 — 세이브·AI 이양·소유권
테이블이 전부 지역 id로 걸려 있으므로 기존 id의 정체성은 건드리지 않는다.

**소유권 테이블 동기화(안 하면 조용히 깨지는 부분)**: 지도(geojson
`properties.owner`)와 게임(world.json `regionOwnershipOverrides`)이 다르면
Nations.jsx의 `divergedRegionIds`가 "캠페인 중 주인이 바뀐 땅"으로 읽고 정복선을
그린다. 재단 결과를 테이블에 되쓰지 않으면 **1턴째부터 가짜 정복선이 21개**
떠 있게 된다. 되쓰기 54건 수행.

**실측(1939-09-01 z4 유럽 덤프 · 지역 3,662 → 3,693 · 빌드 12초)**

| 버킷 | 수 | 뜻 |
| --- | --- | --- |
| 무접촉 | 3,059 | 시대 면이 안 닿음 → 스펙 배정 유지(사다리 2단) |
| 확인 | 549 | 면이 스펙과 같은 답 |
| 재배정 | 21 | 면이 **다른** 답 → 면이 이긴다, 전건 기명 |
| 절단 | 30 (조각 +31) | 두 나라로 실제 분할 |

재배정 21건은 손으로 짠 스펙이 틀렸던 곳들이고, 전부 역사적으로 맞다:
BLR/UKR 6개 州 소련→**폴란드**(크레시 — 소련 침공은 9월 17일, 개전일엔 폴란드
땅), UKR.23_1 소련→**헝가리**(카르파티아 루테니아, 1939년 3월 병합).
절단 30건의 대표: CZE.7_1(독일/폴란드 — 자올지에), SVK 다수(슬로바키아/헝가리 —
제1차 빈 중재선).

**상수 근거(측정 기반, 추정 금지 원칙)**: `MIN_PIECE_FRACTION = 2%`.
두 데이터셋이 같은 국경을 각자 그리면 공유 국경마다 실오라기가 남는다(시대
면은 0.01° 데시메이트 + 0.06° 용접). 실측 분포에 깨끗한 간격이 있다 —
**접힌 노이즈 최대 지분 1.95%**(MAR.12_1/Spain) vs **살아남은 절단 최소 지분
2.1%**, 중앙 19.6%, 최대 45.2%. 2%는 그 사이에 있다. 노이즈는 버리지 않고
**다수 소유주에 흡수**한다(면적 보존 — 지도에서 사라지지 않는다).

**이름 해소**: 면 36/36 매칭. 자동 경로는 스펙 폴리티(이름·코드·별칭) + 현대
국가명(unassignedKeepModernOwner일 때) 정확 일치 → 양식 정규화("Kingdom of
Hungary"→Hungary, 3건, 사람 눈 확인 권장으로 출력). 나머지 18건은 **식민지
계열** — 이름이 위치는 말해도 소유주는 절대 말하지 않으므로 스펙의
`eraGeometry.faceOwners`로 명시 배정(알제리·튀니지·레바논→FRA, 리비아·알바니아
보호령→ITA, 키프로스·몰타·지브롤터·걸프 보호령들→GBR, 리오데오로·이프니→ESP,
이라크는 독립국이라 자기 이름 유지).

**남은 흠**: 클립 실패 6건(IRL.7_1, LTU/LVA remainder) — 해당 지역은 현대
모양·스펙 소유주를 유지하고 경고로 출력한다. polygon-clipping의 알려진
출력 링 실패 계열이고, 조용한 성공으로 위장하지 않는 것이 현재 처리다.

**다른 프리셋으로 확장하는 법**: 스펙에 `eraGeometry` 추가 → 사용자 PC에서
그 날짜의 추출·페치·조립 3단 실행 → 재빌드. 덤프가 없으면 빌드는 예전과
똑같이 돌고 "사다리 2단으로 진행"이라고 말한 뒤 만들 명령을 인쇄한다.

## F-3 후속: 오데르-나이세 오진 추적 (2026-08-09 — 플레이어 관측)

플레이어가 첫 접합 이미지를 보고 "서부 국경이 오데르-나이세 아니냐"고 지적 —
맞았다. **OHM 데이터는 옳았다**: Polska 면은 슈체친·브로츠와프·단치히·
쾨니히스베르크를 제외하고 포즈난·그디니아·바르샤바·리비우를 포함한다(점 검사
실측). 문제는 **독일 면이 없었다**는 것 — 룩셈부르크·슬로바키아 라벨과 한 면에
갇힌 충돌 면(84.15 deg²)이었고, 조립기는 충돌 면을 원칙대로 거부했다. 그래서
서부 폴란드 州들은 어떤 면에도 닿지 않아 스펙 배정(=현대 소유주 폴란드)을
유지했고, 결과가 1945년 국경이었다.

수리 4건, 전부 실측 근거:

1. **융합 면 해소(`--resolve-conflicts`)** — 클로드 코드 리뷰 2번의 이행.
   면 안에서 **가장 깊은 라벨**(면 가장자리까지 최단거리 최대)이 가져간다.
   독일 0.4365 / 슬로바키아 0.118 / 룩셈부르크 0.0575 → 독일. 가드 2개:
   라벨 4개 이상이면 융합이 아니라 붕괴로 보고 거부(지중해 메가면 11개 —
   깊이 규칙만 쓰면 **시리아**가 가져간다, 실측), 승자 깊이가 2위의 2배 미만이면
   거부(스페인령/프랑스령 모로코 1.98배 → 거부, 맞는 판단).
2. **삼킨 이름에 대한 권위 거부** — 해소된 면은 승자의 윤곽으로는 쓰되,
   삼켜진 폴리티(룩셈부르크·스웨덴·슬로바키아)의 지역엔 적용하지 않는다.
   32건 거부. 이게 없으면 스웨덴 전역이 핀란드가 된다(실측).
3. **경계선 관계 필터 버그** — `\b`는 ASCII 전용이라 "Граница СССР-Финляндия"가
   폴리티로 통과해 면을 차지하고 충돌까지 만들었다. 구분자 전방탐색으로 교체,
   3건 제외.
4. **미국 중심점 거짓말** — 태평양 속령까지 포함한 bbox 중심이 **이집트
   (26.18, 28.42)**에 떨어져 이집트 왕국 면을 가로챘다. center-overrides에 추가.

접합기 쪽 추가 안전장치 2개:

- **유효폭 하한 0.06°**(= 용접 거리): 지분 하한 2%는 큰 州엔 맞지만 작은 州엔
  못 쓴다(스위스 칸톤의 10%는 실오라기, 우크라이나 州의 10%는 전쟁). 폭 =
  면적/최장 bbox 변. 절단 소수측 실측 유효폭 최소 0.062° · 중앙 0.176°로,
  하한 바로 위에서 시작한다.
- **`excludeFaces` / `faceKeepOut`**: 기하학만으로는 판별 불가능한 두 결함을
  스펙이 명시한다. 창 잔여 면(ایران 라벨, 1191 deg², 41×45° 스팬 — 2위의 6배)
  배제, 그리고 **독일 면의 유틀란트 침범**(미트윌란 97.8%·쉬드단마르크 67.8%
  실측 — 독·덴 국경이 안 닫혔고 덤프에 1939 덴마크 관계가 없어 융합 표시조차
  안 된다) 차단.

**수리 후**: 재배정 21→24, 절단 30→34, 커버리지 확대. 서부 폴란드
(자호드니오포모르스키에 99.9%·루부스키에 99.5% 독일 면 내부)가 독일로 넘어가
1939년 국경이 그려진다. 덴마크는 온전. 눈 검수 이미지 갱신.

## 중세 하이브리드 (rung 2+3) 설계 — 2026-08-14

대상: medieval-1200(실측 30면/13.1%) · mongol-1300(29/19.6%) ·
magna-1444(28/14.1%) · roman-117(3/3.7%). 공백의 정체는 확정돼 있다 —
OHM이 그 시대에 폐합하지 못하는 정치체들(독일 코어 부재는 08-12 양 전송로
교차 조사로 종결). 처방은 사다리 3단(historical-basemaps) 백필이고, 이
절이 그 설계다.

### 원천 파일과 날짜 매핑 (2026-08-14 GitHub API로 목록 실측)

aourednik/historical-basemaps `geojson/`의 세계 지도는 연도별 단일
GeoJSON(~1MB, GPL-3.0, 레포 스스로 대륙 스케일 정확도를 경고)이다. 우리
날짜 매핑과 근거:

| 보드 | 파일 | 근거 |
|---|---|---|
| medieval-1200 | world_1200 | 연도 정확 일치 |
| mongol-1300 | world_1300 | 정확 일치. world_1279(원 정점)가 대안 — 눈 비교 후 확정 |
| magna-1444 | world_1400 | **비잔티움 생존이 결정적**(1453 함락 전). world_1492는 비잔티움·그라나다 소멸 후 |
| roman-117 | world_200 | **다키아 포함이 결정적**(106 정복). 117 정점의 메소포타미아(114-117)만 놓침 — 기록하고 수용 |

다운로드는 OHM 페치와 같은 정책으로 **PC 전용**(클라우드는 WebFetch만
허용이고 데이터 파일 경로가 아님):
`curl -L -o scripts/ohm/data/world_<YYYY>.geojson https://raw.githubusercontent.com/aourednik/historical-basemaps/master/geojson/world_<YYYY>.geojson`
× 4. 파일은 scripts/ohm/data/에 커밋한다(개인 클론, 재배포 없음 — 재현성
우선; center-overrides와 같은 서랍).

### 구조 — 백필은 조립 산출물 위의 별도 패스

`scripts/ohm/backfill-era-faces.mjs <era-borders.geojson> --world <world_YYYY.geojson> [--out]`

1. rung-1 면(조립·명명 완료)을 읽는다 — 무수정 통과.
2. world_YYYY 폴리곤을 프레임 사각형(frameOf 동일 규칙)으로 클립하고
   0.01° 데시메이트한다.
3. **커버 판정은 표본 격자**(faceLandFraction의 소성수 격자 재사용):
   world 폴리곤의 내부 표본 중 rung-1 면 안에 떨어지는 비율이 문턱(초안
   0.5 — 첫 실측으로 확정) 이상이면 "이미 rung-1이 담당" → 스킵·카운트.
   미만이면 폴리곤 전체를 `rung: 3` 태그로 산출물에 추가한다.
   **기하 차집합은 하지 않는다** — 대륙 유니온 차집합은 08-09 해안
   유니온 폐기와 같은 함정이다.
4. 이름: world의 NAME 속성 → 스펙 폴리티 매칭은 그래프트의 기존 기계
   (이름 색인 + 별칭 + faceOwners)를 그대로 탄다. 보드별 별칭 패스는
   08-14 여섯 날짜 패스와 동일 절차. 미매칭 전건 인쇄.
5. 리포트: 백필 폴리곤 전건(추가/스킵/이유), 예상 커버리지 전후.

### 그래프트 규칙 하나 추가 — 지역 단위 rung-1 우선

면이 겹치면 조각 접기가 이중 계산에 빠지므로 기하로 풀지 않는다.
빌드(build-preset)의 지역 루프에 규칙 하나: **rung-1 면이 하나라도 닿는
지역은 rung-3 면을 전부 무시한다.** rung-1의 손이 안 닿는 지역만 rung-3가
자른다. 이음매는 최악의 경우 현대 지역 폭만큼의 계단인데, rung-3 자체가
대륙 스케일이라 허용 오차 안이다. 리포트에 rung1/rung3/무접촉 버킷을
나눠 전건 인쇄한다.

## 실행 환경 메모

추출은 Node 스크립트(오프라인, 사용자 PC 또는 개발 클론)로 돈다.
클라우드 세션에서 돌릴 땐 타일 fetch가 필요하므로, 브라우저 컨텍스트
(앱이 이미 쓰는 타일 서버) 경유로 원자재를 받는 경로가 검증돼 있다.
의존성은 저장소에 이미 있다: pmtiles, @mapbox/vector-tile, pbf,
polygon-clipping (+ 폴리곤화에 turf 계열 추가 필요).
